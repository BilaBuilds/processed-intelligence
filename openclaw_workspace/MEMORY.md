# ProcessEd — OpenClaw Memory Index

This workspace is the memory and operator-intelligence sidecar for the ProcessEd
tender pipeline. It is read and written by deterministic Python scripts; it is NOT
generated by AI and does NOT influence pipeline scoring or shortlist decisions.

## What lives here

| Path | Contents |
|------|----------|
| `memory/` | Cross-run operator notes, sector context, persistent facts |
| `buyers/` | One dossier per tracked buyer (`{buyer_slug}.md`) |
| `sectors/` | Sector-level intelligence notes (construction, social housing, …) |
| `outreach/` | Draft outreach notes, contact prep, send history |
| `runs/` | Per-run summary notes (`{run_id}.md`) |
| `dashboards/` | Snapshot exports and timing watchlist summaries |

## How it is updated

Run `python scripts/sync_to_openclaw.py` after any pipeline run.
The sync script reads deterministic pipeline artifacts and writes/updates markdown files.
It never calls an LLM. It never modifies pipeline state.

## How to query it

```
python scripts/query_openclaw.py --due-soon
python scripts/query_openclaw.py --contact-list
python scripts/query_openclaw.py --changed-since <run_id>
python scripts/query_openclaw.py --signals
python scripts/query_openclaw.py --sector construction
python scripts/query_openclaw.py --strongest
```

Or open any dossier file directly — they are plain markdown, readable by Claude,
OpenClaw, or any text editor.

## Source of truth

ProcessEd pipeline artifacts are always the source of truth.
Memory files here are derived views. If they conflict with pipeline artifacts,
trust the artifacts and re-run the sync.

## Operator notes

Add free-text notes to any dossier's `## Memory Notes` section.
The sync script never overwrites that section — it only updates data fields above it.
